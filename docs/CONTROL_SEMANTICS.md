# Временные ручки и конечная точка

Проверено по DSP и официальным руководствам 2026-10-09.

## Что принято у аналогичных инструментов

[FabFilter Pro-C: Time controls](https://www.fabfilter.com/help/pro-c/using/timecontrols)
определяет Attack как скорость набора компрессии, Release как восстановление
после подавления. Hold продлевает удержание, Lookahead упреждает пики.
Attack не является отдельной паузой с последующим мгновенным подавлением.

[ShaperBox 3 Manual](https://downloads.cableguys.com/Cableguys-ShaperBox-3-Manual.pdf),
раздел VolumeShaper 7 (стр. 25), описывает громкость по нарисованной LFO-кривой;
Envelope Follower/Compressor отделены от этого режима. Разделы Envelope Follower
(стр. 47–49) и Compressor (стр. 56–57) используют обычные Attack/Hold/Release.
[LFO Tool](https://xferrecords.com/products/lfo-tool) также предлагает редактор
точек/кривизны, формы и темповую частоту LFO.

Вывод для KickDuck1: текущая архитектура — триггерный редактор усиления, а не
обычный компрессор с огибающей. Его ручки должны описывать геометрию; называть
финальный участок Attack было неоднозначно.

## Текущая привязка

| Ручка | ID для DAW | Что делает |
| --- | --- | --- |
| ATTACK | onsetAttack | 0–100 мс до первой точки; X = Attack / длительность цикла, ограничен второй точкой |
| LENGTH | length | X второй точки = Length / 2 с ограничением соседями |
| RECOVER (раньше RELEASE) | release | X третьей точки = Recover / длительность цикла в мс |
| TAIL (раньше ATTACK) | attack | X предпоследней точки = 1 − Tail / длительность цикла в мс |

Ни одна ручка не задаёт задержку старта. При Attack=0 первый sample распознанного кика
получает глубину первой точки мгновенно. При ненулевом Attack подавление
нарастает от нуля до первой точки; скруглённый режим использует smoothstep
с нулевыми касательными на концах. При повторном кике стартует с текущей глубины. При первой точке вверху это будет
нулевое начальное подавление, при первой точке внизу — глубина Amount.
На плоском хвосте действие TAIL может быть неслышно: перемещение точки
среди других точек той же глубины не обязано менять кривую.
RECOVER означает время достижения точки; полное восстановление там происходит
только если её глубина нулевая.

Поменялись только видимые имена Attack → Tail и Release → Recover.
ID, диапазоны, связь с точками и автоматизация сохраняются. Новый начальный Attack добавлен отдельным параметром `onsetAttack`
в конце списка параметров. Параметр появился в v4; текущее состояние v5. Отсутствующий параметр в старых
состояниях явно восстанавливается как 0 мс. Геометрия хранит прежние пять
точек с первой X=0; начальный якорь без подавления добавляется неявно
при вычислении. Пресеты/RESET возвращают Attack к 0 мс.
Это конечный геометрический участок, а не программно-зависимая постоянная
компрессора. Перепад лишь 2% не даёт полезного диапазона начального подавления.

## Последняя точка

Это конечная глубина, не кнопка bypass и не переключатель детектора.
Она формирует прежде всего поздний участок от предпоследней точки; в
скруглённом режиме её значение также влияет на соседний наклон.
Пример при 120 BPM: один цикл = 500 мс, при Tail=50 мс предпоследняя точка
стоит на 450 мс. Конечная точка внизу добавляет позднее подавление; вверху
возвращает к нулевой глубине. По завершении цикла DSP переходит к dry за
предусмотренное ограничение скорости (до 2 мс на полный диапазон).

Следующий кик перезапускает фазу с нуля. Если он пришёл на 250 мс, поздний
хвост предыдущего цикла не проигрывается. Поэтому точка может казаться
неработающей при частом ритме. Тест сравнивает крайние глубины 0/1:
на одиночном кике выход перед концом меняется более чем на 0.3 при bass=0.5
и Amount=70%; при повторе каждые 250 мс сравниваемые ранние участки одинаковы.
Отдельные регрессии проверяют все пять точек и их влияние на звук.

Практический вывод для одноразового ducking с ровным возвратом: конечную точку
удобно поставить на нулевую глубину (верх графика), как в Punch/Smooth/Long/Gate.
Classic и Swell намеренно допускают повторный провал в конце; формы пользователя
автоматически не меняются. Это рекомендация из текущей модели, а не универсальное
требование ко всем редакторам LFO.

## BPM без AUX и границы ручек — 2026-10-09

ATTACK расширен до 100 мс (ограничен второй точкой). Отключённый AUX
теперь включает ducking по одной доле BPM: PPQ транспорта используется
во время воспроизведения, иначе непрерывный цикл; fallback 120 BPM.
Подключённый, но тихий AUX остаётся в режиме запуска от кика. Переход
назад к подключённому AUX завершает автономное подавление и ждёт кик.
GUI обозначает отключённый AUX как BPM DUCKING.

RECOVER и TAIL имеют динамические GUI-диапазоны по соседним текущим
точкам. DSP больше не ограничен устаревшим положением хвоста в сохранённой
геометрии. При конфликтующей автоматизации Recover имеет приоритет,
Tail остаётся справа от него. Значения GUI показывают эффективное время;
открытие GUI не переписывает параметры автоматизации DAW.
Состояние v5 переводит v2–v4 в прежнюю эффективную геометрию и соответствующие
значения параметров, сохраняя интерполяцию. Старые ID Tail/Recover и диапазоны
DAW сохранены. Attack хранится в состоянии в физических миллисекундах;
расширение диапазона может изменить внешние огибающие DAW, если хост хранит
автоматизацию этого нового параметра нормализованно. Плагин не может
переписать такие огибающие хоста.
