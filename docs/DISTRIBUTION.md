# Комплект выпуска 1.0.0

Подготовленный локальный пакет Linux x86-64 содержит VST3, Standalone,
руководство, установку, changelog, метаданные сборки и контрольные суммы.
Два предоставленных автором скриншота включены в docs/images и используются
в README и руководстве. Проекты REAPER и остальные личные файлы не включены.

## Статус и лицензия

Автоматические проверки и пользовательская проверка REAPER пройдены.
GitHub Release и тег не создавались. KickDuck1 распространяется под
GNU AGPLv3, SPDX: AGPL-3.0-only; полный текст — [LICENSE](../LICENSE).
JUCE используется по AGPLv3, включённый VST3 SDK — по GPLv3.
См. [сторонние компоненты](../THIRD_PARTY_NOTICES.md).

Сценарий создаёт два архива: бинарный linux-x86_64 и соответствующий source.
Публиковать их нужно вместе: source содержит файлы проекта, сборочные скрипты
и использованный JUCE в build/_deps/juce-src для offline-конфигурации.
Исходники системных библиотек не включаются. Лицензии компонентов сохранены.
Для выпуска используйте чистый checkout и бинарники, собранные из него;
BUILD_INFO фиксирует ревизию упаковки, а не доказывает происхождение бинарника.

## Подготовка пакета

Для упаковки нужны Python 3.11+, Git и `readelf` из GNU binutils.

```sh
cmake --preset offline
cmake --build --preset tests
ctest --preset dev
cmake --build --preset plugin
python3 scripts/package_release.py
```

В новом checkout сначала используйте `cmake --preset dev` для JUCE.
Архивы и их `.sha256` находятся в `build-dev/dist/` и не входят в Git.
Проверяйте BUILD_INFO.json: архитектуру, требуемые версии библиотечных символов,
Git revision и список зависимостей. Пакет не является универсальным Linux-бинарником.
Для более старых систем потребуется отдельная сборка и проверка на выбранном baseline.

После распаковки `sha256sum -c SHA256SUMS` проверяет файлы комплекта.
Перед выпуском проверьте установку на целевой машине и доступность
обоих архивов для получателей. Состав лицензий в THIRD_PARTY —
сопроводительные файлы из использованного JUCE, а не юридическая экспертиза.

## Проверки 2026-10-17

Пользователь подтвердил работу полного SAVE/LOAD, восстановление выбранного B,
автоматизацию, несколько экземпляров и offline render в REAPER.
На предоставленных скриншотах видны два экземпляра с разными настройками
и огибающая Amount. Скриншоты подтверждают визуальное состояние, а не звучание;
слуховая и экспортная приёмка основаны на отчёте пользователя.

Автоматическая часть: два набора CTest, разные частоты/размеры блоков,
шесть размеров GUI, сериализация, валидация пресетов и отдельный конкурентный
тест. Методика и границы — [REALTIME_AUDIT.md](REALTIME_AUDIT.md).
